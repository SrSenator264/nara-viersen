# خطة: Serverless لاستقبال طلبات الموقع لما ينقطع نت المحل (Flamo)

## شو هو Serverless؟
نكتب دالة صغيرة ونرفعها، والشركة (Cloudflare / AWS / Vercel) بتشغّلها عنا. ما في سيرفر نصيّنه، وبندفع بس على قد الاستخدام.

## المقارنة مع نظامنا الحالي
| | الحالي (كمبيوتر المحل + Cloudflare Tunnel + Tailscale) | Serverless |
|---|---|---|
| الكلفة | صفر تقريبًا | 0–5€ بالشهر |
| الصيانة | علينا | ما في |
| إذا انقطع نت المحل | الموقع والتطبيق بيوقعوا | الموقع بيضل شغال |
| الطابعات و TSE (USB) | شغالين محليًا | ما بيوصلوا إلهم |
| جسر Lieferando (Playwright) | محلي | ما بيناسب |
| بيانات الزبائن والمبيعات | عندنا بالمحل | عند طرف ثالث |
| حمل ~40 طلب باليوم | مو مشكلة | مو مشكلة |

## القرار
- **ما ننقل شي من النظام الحالي.** الكاشير والمطبخ والسواقين والطباعة والجسور بتضل محلية.
- المشكلة الوحيدة اللي بيحلها: **انقطاع نت المحل** بيوقّع موقع الزبائن ونخسر طلبات.

## الفكرة (لاحقًا، مع الموقع)
استقبال طلبات الموقع العام يكون على Cloudflare Workers أو Pages:
1. الزبون بيطلب من الموقع، والدالة بتحفظ الطلب (قاعدة صغيرة مثل D1 أو KV).
2. كمبيوتر المحل بيسحب الطلبات الجديدة، وأول ما يرجع النت بيستلم اللي تراكم وبيطبعها.
3. إذا النت واقع أكثر من مدة معينة: تنبيه Telegram + الموقع بيعرض "مغلق مؤقتًا" أو بيقبل الطلب مع تنبيه تأخير.

## الكلفة التقريبية (تأكد من صفحات الأسعار وقت التنفيذ)
- Cloudflare Workers: مجاني لحد 100 ألف طلب باليوم، والمدفوع 5$ بالشهر.
- AWS Lambda: حوالي مليون طلب مجاني بالشهر. انتبه لكلفة API Gateway.
- Vercel: خطة Hobby للمشاريع غير التجارية فقط، فمطعم = Pro بـ 20$ بالشهر.
- المتوقع لمطعمنا: **0–5€ بالشهر** مع Cloudflare، ونفعّل تنبيه ميزانية.
