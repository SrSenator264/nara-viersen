# خطة: Playwright لفحص Flamo + استكشاف المواقع

## الهدف
نستعمل Playwright (موجود أصلًا بالريبو، `playwright ^1.63.0`، وبيستعمله جسر Lieferando) لثلاث أشياء:
1. **اختبارات أوتوماتيكية** لسلسلة الطلب كاملة.
2. **استكشاف مواقع** ندرس تصميمها وطريقة عملها ونصمم شي مشابه لإلنا (مو نسخ).
3. **أتمتة مهام متكررة** (مثلًا حسابات الأعمال على السوشيال ميديا، بس عبر الـ API الرسمي).

## 1) اختبار السلسلة الكاملة (الأولوية)
الكاشير ← المطبخ ← Live Orders ← السائق ← التسليم.

**الطريقة:**
- نافذة لكل دور (كاشير، مطبخ، Live Orders، سائق) بنفس الاختبار.
- بيانات تجريبية فقط (وضع Demo): بدون طباعة تذاكر حقيقية، بدون إشعارات للسائقين الحقيقيين، بدون دفع حقيقي.
- لقطة شاشة + فيديو عند أي فشل.
- فحص بحجم موبايل وكمبيوتر.
- ملف الاختبار: `tests/e2e/order-flow.spec.mjs` وأمر تشغيل: `npm run test:e2e`.

### Definition of Done (للاختبار الأول)
**لازم يشتغل:**
- يفتح الكاشير، يضيف منتج، يعمل طلب Delivery تجريبي.
- الطلب بيظهر بالمطبخ، وبيتغير حالته (قيد التحضير ← جاهز).
- الطلب بيظهر بـ Live Orders بالحالة الصح.
- يتعيّن سائق تجريبي وبتتغير الحالة لـ "بالطريق" ثم "تم التسليم".
- الاختبار بيعمل تنظيف لبيانات الاختبار بعد ما يخلص.

**ملاحظات حدّية (Edge cases):**
- طلب Pickup (بدون سائق).
- طلب بدون اتصال إنترنت مؤقت أو إعادة تحميل الصفحة بنص الطريق.

**مو blocker:**
- اختبار الطباعة الفعلية، الدفع الحقيقي، Lieferando/Uber الحقيقيين.
- تطابق بكسلي للتصميم.

## 2) استكشاف المواقع (Reverse Engineering للتصميم)
**شو ممكن:** أفتح موقع عام بالمتصفح، أدرس البنية (الأقسام، الألوان، الخطوط، الـ Layout، الأنيميشن، تدفق الصفحات) وأقترح تصميم مشابه بروح Flamo.

**حدود لازم نلتزم فيها:**
- نتعلم الفكرة والبنية، **ما ننسخ** الكود ولا الصور ولا النصوص ولا اللوغو (حقوق نشر ومخاطر قانونية).
- نصمم بهوية Flamo (الشعلة، الألوان، اللغة).
- ما بنفك حمايات ولا بنتجاوز تسجيل دخول مو إلنا.

## 3) إنستغرام / فيسبوك / تيك توك
**الصراحة:** تقنيًا Playwright بيقدر يفتحهم، بس **ما بنصح** نأتمت الدخول والنشر بالمتصفح:
- بيخالف شروط الاستخدام وفي خطر **حظر الحساب** (وخصوصًا حساب المطعم).
- الطريقة الصح: **API الرسمي** (Meta Graph API لإنستغرام وفيسبوك، TikTok API) لنشر المحتوى وقراءة الإحصائيات والرسائل لحساباتك أنت.
- بدك تسجل دخول بنفسك، وما تعطيني كلمات سر بالشات.

**الاستعمال المقبول:** قراءة صفحاتنا العامة لنراجع شكلها، أو جمع أفكار محتوى من صفحات عامة بدون تجاوز حماية.

## المراحل
1. نجرّب أول اختبار بسيط (فتح الكاشير + طلب تجريبي).
2. نوسّعه للسلسلة كاملة حسب الـ DoD فوق.
3. نربطه بـ GitHub Actions أو سكربت محلي يشتغل بعد كل تحديث.
4. بعدين نفتح موضوع الاستكشاف (القسم 2) على موقع واحد كتجربة.
5. السوشيال ميديا: نبدأ بدراسة الـ API الرسمي لحساب واحد.
